# 잘린 문자 위첨자 및 MC 조립 수정

기준 자료는 `20260928_235336_912734/results_235412_239290.json`이다.

## 변경

- 단일 알파벳 위첨자는 점수 0.9 이상을 요구한다. OCR 입력의 오른쪽 여백이 본문 검출 높이보다 작으면, 잘린 단어·표식의 일부일 수 있어 변환을 거부한다. 이미지 크기가 제공되는 실제 GUI·자동화 경로에서 적용하며, 거부 사유를 기록한다.
- 완전한 두 글자 TM/MC 및 숫자 위첨자의 기존 조건은 유지한다. 원문이나 박스는 변경하지 않는다.
- 기대 문장에 🅪가 있을 때, 공백 없이 붙은 MC/Mc/mc/mC를 위치 정렬용 한 토큰으로 다룬다. 두 글자의 일부가 다른 위치로 밀리거나 C만 위첨자 위치에 배치되는 문제를 줄인다.
- 실제 관측의 대소문자와 공백을 그대로 투표한다. MC/Mc를 🅪로 변환하지 않고, 틀린 관측을 삭제하거나 확인된 표식에 가중치를 주지 않는다. 원래 확인·비교 조건은 유지한다.

## 검증

- 전체 테스트 638개 통과(UTF-8 환경).
- 로그의 실제 박스와 점수, 전처리 입력 크기로 단일 문자 거부 조건을 재생했다. 당시 모든 프레임 픽셀은 없으므로 이 검사는 실제 OCR 재실행이 아니다. 결과: TC6 ROI2의 `O → ᴼ`, TC3의 `M → ᴹ` 변환을 거부한다.
- 최신 관측 문자열을 새 조립 로직에 재생한 TC3 결과는 `Nettoyage de la buse ezDispenseMc`. 마지막 위치 투표는 🅪 1, Mc 6, MC 1, M 1이다. 조립은 완료되지만 정확한 문자열이 아니므로 FAIL을 유지한다.
- TC5 ROI1은 아포스트로피 삽입 등으로 여전히 조립 미완성이다. 이번 수정이 삽입 문자나 MC 인식 오류를 해결한 것은 아니다.
- 이전·최신 스페인어 저장 이미지 8개를 실제 Rapid OCR로 재실험했다. TM 변환과 `OK para introducir.` 중복 보정은 유지됐다. 당시 실행과 동일한 설정임이 모두 보장되는 것은 아니며, 스크립트의 기본 Rapid·직접 ROI 전처리 가정을 사용했다.
- 기록: `captures/replay_mc_clipped_20260929.json`, `captures/replay_tm_overlap_20260929.json`.

동기 캡처와 30초 제한, 사용자 Excel·프리셋은 변경하지 않았다. 추가 OCR 호출도 늘리지 않았다. 수정 후 Vesta 전체 실행은 수행하지 않았으며, 전체 TC 통과 여부는 재검증이 필요하다. 커밋·push하지 않았다.
