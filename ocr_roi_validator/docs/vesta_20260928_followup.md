## TC2: 주기 수가 아닌 연속 확인 조건

ROI1의 실제 검증 모드는 `content`다. `required_cycles=1`, `completed_cycles=0`은 이 모드의 최종 조건이 아니다.

`comparison_passed`는 현재 한 프레임과 전체 정답의 비교다. 스크롤 조각이 전체 문장과 다르므로 false여도 누적 조립은 맞을 수 있다. 기존 `eligible`은 누적 조립의 판정이며, 그 뒤 현재 프레임의 유효성과 연속 확인을 추가 검사한다.

연속 확인은 유효한 관측 2회 이상, 처음 확인부터 0.5초 이상을 요구한다. 문자 치환이 있는 프레임, 정렬되지 않는 프레임, 조립 불일치 프레임은 확인을 초기화한다.

- 프레임 9: 조립 일치, 깨끗한 관측으로 확인 1회.
- 프레임 10: `Temp. Eal`의 끝 `l` 치환으로 초기화.
- 프레임 11: 확인 1회.
- 프레임 12: `froic`의 끝 `c` 치환으로 초기화.
- 프레임 13: 확인 1회.
- 프레임 14: 시간 초과.

따라서 마지막 조립 문자열은 맞지만 확인이 끝나지 않았다. 저장 관측을 자동 검증 루프에 재생한 회귀 테스트도 FAIL_TIMEOUT이다. 마지막에 깨끗한 관측을 하나 더 제공한 대조 테스트는 주기 0에서도 PASS한다. 통과 정책은 변경하지 않았다.

추가 진단 필드: `final_eligible`, `confirmation_related`, `confirmation_samples`, `confirmation_passed`, `confirmation_reason`.

## 커버리지와 조립 완료

커버리지는 각 위치에 한 번이라도 관측 문자가 배치됐는지의 비율이다. 정확한 문자나 투표 우세를 뜻하지 않는다. `missing_characters`도 아예 관측이 없는 위치만 표시한다.

| 대상 | 관측 충돌 | 결과 |
| --- | --- | --- |
| TC3 ROI1 | 공백 제외 28번째 위치에서 `M`:1, `C`:1 | 커버리지 100%, 누락 없음, 조립 미완성, 공백 PENDING |
| TC5 ROI1 | 공백 제외 4번째 위치에서 `t`:1, `:`:1 | 커버리지 100%, 누락 없음, 조립 미완성, 공백 MATCH |

`unresolved_characters`에 위치와 실제 문자별 관측 수를 기록하도록 추가했다. 정답에서 문자를 채우지 않는다.

## TC5 하이픈 및 처리 시간

기존 실행에서 ROI2의 전체 OCR 요청 시간 합은 20.875초, ROI1은 8.999초다. 동기식으로 두 ROI를 순서대로 처리하므로 ROI2가 다음 캡처 시점을 늦추는 구조를 확인했다. 두 ROI 모두 요청 4회였고, ROI2의 마지막 요청은 시간 초과다. 20.875초 전부를 추가 재인식 시간으로 해석하면 안 된다.

저장된 `first_ocr_frame.png`에 기록된 전처리(margin 8, 최소 길이 160, 긴 ROI 패딩, 확대)를 적용했다. Rapid 기본 엔진과 직접 ROI 경로를 사용했다. 당시 모델 선택과 context 모드가 결과 JSON에 없으므로 이 두 설정은 재실험의 명시적 가정이다. 최종 실패 폴더의 재구성 입력을 당시 실제 입력이라고 간주하지 않았다.

재실험에서 원문, 글자 덩어리 22개, 줄 영역 `[4,8,311,41]`, 단어 영역, 추가 OCR 출력과 점수가 기존 기록과 일치했다. 추가 출력은 `Nettoyage`, 빈 문자열, `Appuyez`다. 하이픈 보완은 계속 실패한다. 작은 왼쪽 요소 보존 옵션과 좌우 문맥을 확장한 별도 실험도 하이픈을 복원하지 못했다.

## 최소 변경

1. 공백 재인식 실패를 동일한 줄 픽셀·크기·원문에 한해 10초 동안 재시도하지 않는다. 입력이 바뀌면 즉시 재시도한다. 언어나 엔진이 바뀌면 캐시를 교체한다. 최대 16개 항목만 보관한다.
2. 실패만 재사용한다. 성공 OCR을 캐시해 독립 관측 수를 늘리지 않는다. 생략한 요청은 `retry_calls=0`과 `previous_attempt`를 기록한다.
3. 추가 단어 OCR은 최대 6회이고, 경과 시간이 6초 이상이면 다음 호출을 시작하지 않는다. 진행 중인 네이티브 호출을 6초에 강제 중단하는 제한은 아니다. 기존 자동화의 30초 감시 제한은 유지한다.
4. 프레임별 공백 보완 진단, 연속 확인 진단, 문자 투표 충돌을 추가한다.

동기 캡처, 정답 비교 기준, MC 기하 조건은 유지했다. 악센트 보정 경로는 변경하지 않았다.
